# Changelog

## Unreleased

- `writing-docblocks` gives docblocks and inline comments separate rules. `references/comments.md` becomes `references/inline-comments.md`, and a new `references/docblocks.md` holds the docblock rules. A docblock is a contract for a caller who never opens the body, so a rewrite of the body that keeps its inputs, outputs and side effects leaves the block alone. Its summary starts with a third-person verb. Parameter descriptions say what the value means: unit, accepted values, default, and what empty or null does. A fact two functions share is explained once, on the function it belongs to. An inline comment makes sense on its own, without "as above" or "same reason". A reason that needs a paragraph moves to the commit, an ADR or the docs, behind a one-line pointer. A `TODO` carries an owner and a ticket.
- `writing-docblocks` lets a comment give a reason. A comment is worth its line when it says what the code cannot: the reason behind an approach, an exception or a value. One that restates the code is the one to cut. This departs from the WordPress handbook's advice to avoid the why, and `SKILL.md`, `php.md` and `javascript.md` say so where they quote it. The §3 example keeps the line explaining its 200 words per minute. `docblock-guard.sh` no longer reports a reason, and keeps its history and run-length checks.
- `writing-docblocks` writes `@return void` on a function that returns nothing, where `php.md` had kept to the WordPress handbook's restriction of it to core's bundled themes and compatibility shims.
- `writing-docblocks` indents with tabs inside a block, as in the rest of the file. Spaces remain only for aligning the type, variable and description columns, since a tab's width varies by editor. `docblocks.md` holds the rule, and `php.md` and `javascript.md` point to it. `generic.md` indents continuation lines one tab further than the `@`. A file in a format that takes spaces, such as Python, keeps them.
- The four skill guards run again. `${CLAUDE_SKILL_DIR}` is substituted into a skill's `allowed-tools` and body text, never into a hook command, and never exported to the hook process, so every guard path built from it expanded to `/scripts/...`. The four hooks had failed on each matching write since 2026-09-11, 1,178 times across the transcripts, reporting `/bin/sh: /scripts/docblock-guard.sh: No such file or directory` and running none of their checks. Under a plugin install the guards now register in `hooks/hooks.json` through `${CLAUDE_PLUGIN_ROOT}`, which the hook runner does export, and each gates on its own skill having been invoked, so the timing the skills describe is unchanged. The frontmatter declaration stays for a skills-CLI install, resolving under `$HOME/.claude/skills/` and exiting 0 where that path is absent.
- `handoff` is cut to four sections (Goal, State, Dead ends, Next step) and a 3,000-character budget, replacing six sections and a 120-line ceiling. Documents met the old ceiling with long lines, and one held 8,725 bytes in 48 lines. The Goal is written as a condition `/goal` can take. The Verification section and the list of where routed facts went are gone, because `CLAUDE.md` and auto memory already load each session. Before writing, the skill offers `claude --resume <name>` where the user will return to the same conversation. The channel choice, the branch and worktree tidy-up, and the "tidy up" and "cleanup" triggers are removed.
- `remind-handoff.sh` is removed. It nudged at 200 transcript lines, which one session reached at about 120K tokens of a 1M window. `check-handoff-size.sh` replaces it: a `PostToolUse` hook on `Write|Edit` that reports a `HANDOFF.md` past 3,000 characters.
- `writing-pull-requests` runs its self-review over the whole title and body on a revision, not only the new commits. A section that fails it is rewritten with the ones the commits touched, and a title that no longer names each concern is replaced with `--title`. The split proposal goes to the user in the reply, never into the body.
- `writing-pull-requests` counts concerns as well as lines. A diff with more than one independent concern gets a split proposal, and where kept together, each concern gets its own entry, reason and check. A reason missing from the diff, commits and conversation is asked for. How to verify covers every behaviour described, with each result beside its command. The self-review gains checks for verification scope and per-concern reasons. `anatomy.md` carries the Google and GitHub quotes behind each, verified on 2026-09-28.
- `writing-pull-requests` keeps the title and body to the code change. It leaves out AI attribution, including a harness-supplied attribution line or `Co-Authored-By` trailer, and the Why part no longer asks for the rejected alternative. "Where to start" applies only to a diff with more than one file worth reading. `anatomy.md` keeps the source quotes and drops the instructions `SKILL.md` already gives, and three stale step references now match steps 1 to 5.
- `writing-documentation` offers the dialect, person and type it finds in an existing document or the repo's `CLAUDE.md`, and asks whether to use them or run the interview. The voice and substance terms no longer require sentences a document does not need. Gone are a "you" in every section, first person in the opener, a person in the first screen, and a named limitation. Rules stated in two or three files now live in one, and `attention.md` no longer claims the other writing skills read it.
- Removed `testing-skills` and its runner, `run-matrix.sh`, along with the scenario `tests/` directory each skill carried for it. The plugin ships five skills.
- The plugin registers `hooks/hooks.json` again, so the writing skills load before the work they cover. `docblock-gate.sh` denies a code edit that adds a comment line until `writing-docblocks` is invoked. It empties string literals before matching, so `glob("src/**/*.js")` is not read as a comment. `pr-gate.sh` does the same for `gh pr create` and `gh pr edit`. `pr-nudge.sh` reminds on a prompt mentioning a PR, since a PR written for copy and paste runs no `gh` command. `docs-prose-guard.sh` runs the prose check on documentation paths, which a new `docs_paths` plugin option overrides per user. `record-skill.sh` records each invocation from a `PostToolUse` hook on `Skill`, because the transcript is written asynchronously and can lag the call. A skills-CLI install has no plugin `hooks.json` and gets none of these.
- `writing-pull-requests` opens the PR on "write the PR", "raise a PR" or "open a PR". Only when the user asks for the text alone does it write the title and body to `/tmp/pr-<repo>-<branch>.md` instead, where the user can check and paste them and nothing can commit them. It asks before committing or pushing changes the remote lacks. A `gh pr edit` starts from the live body, rewrites only the sections the change touches, and the reply shows only those sections. `PUSHABLE: NO` stops only a request to open the PR.
- `writing-docblocks` writes a block only where it adds something the name and signature do not, and defaults to a one-line summary plus the required tags. Comments say what the code does, not why, following the WordPress handbook's "Avoid describing "why" an element exists". `references/comments.md` drops the non-obvious-why rule, and SKILL.md §3 gains a before-and-after example. A line starting with a digit now counts as prose in `docblock-guard.sh`, and "is used to" no longer reads as history there, while "this used to" still does.
- `writing-pull-requests` no longer produces a tl;dr. The output is a title and a body, step 2 is gone and the later steps renumber, and the `## tl;dr` heading leaves both worked examples, the anatomy reference and the self-review checklist. The small example's title is now its body's first line, not its second.
- Fourteen sentences of 31 to 47 words across `testing-skills`, `writing-pull-requests` and `audit-vs-fix-discipline` split at the colon that joined two independent claims. No wording changed. `testing-skills` also loses a doubled "either" that the split exposed.
- `check-docblocks.sh` strips a JSDoc `@param` type by counting brace depth. Matching to the first `}` cut `{Array<{countries: string[]}>}` at its inner brace, leaving the row starting at `>`, where the name pattern failed and the parameter was dropped without being counted. The block then read as one row against two parameters, so a correct docblock was reported as a disagreement, beside a closing line telling the reader to fix it.
- `writing-docblocks` ships `docblock-guard.sh`, declared in its frontmatter beside the other two hooks. It flags a comment giving a reason, a comment describing history rather than current state, and a run over three prose lines. Tag rows, multi-line `@return {{...}}` types and markerless `/* ... */` continuation lines each needed handling, having been miscounted in a different direction each time. `README.md` gains its own subsection and moves its hook counts from two to three.
- The `writing-docblocks` description covers an edit that rewrites a comment while the stated task is a fix, a refactor or a styling change. Every other trigger described the comment as the headline of the request, and it almost never is, so the skill went uninvoked across sessions of comment writing.
- `prose-scan.awk` skips a four-space indented code block, which it previously read as prose while skipping fenced blocks and code spans. Indentation under a list item stays prose, so list state is tracked: suppressing every indented line would leave real sentences unchecked, and a missed tell is the worse error. `writing-pull-requests` carries the synced copy.
- `remind-handoff.sh` discards jq's parse errors instead of printing them. It already exited 0 on unparseable input, but the complaint reached the terminal, and a `UserPromptSubmit` hook prints it before every prompt. `prose-tells-guard.sh` already failed open and silent for the same reason.
- `writing-documentation` instructs invoking `writing-docblocks` for inline comments instead of stating that it does not cover them. A boundary is satisfied by stopping, so the referral was read and not acted on.

- `writing-pull-requests` carries its own `references/prose.md`, and the pointers into `writing-documentation` are gone from the other writing skills. A skill installed alone with `npx skills add --skill` no longer references files it does not have.
- `writing-pull-requests` declares the prose hook in its frontmatter and ships its own copy of `prose-tells-guard.sh` and `prose-scan.awk`, so a session that invokes only that skill gets the check. `prose-scan.selftest.sh` fails when any of the three copied files diverges from the `writing-documentation` original.
- Added `testing-skills`: a runner that drives an isolated `claude -p` for a control arm and a treatment arm per scenario, so the arm without the skill carries none of the user's global rules, plus the scenario format and a guide to reading results.
- Every skill carries a `tests/` directory with at least one scenario: a verbatim request, a fixture, and a check script. `audit-vs-fix-discipline` has two. `writing-pull-requests` clones the repository into a bare-backed copy so a push from the run lands nowhere real.
- `run-matrix.sh` keeps each run's `result.json` and writes `usage.txt` (session id, turns, tokens, cost), and the summary totals usage per arm. Before this the runner used text output and no run's cost was recorded anywhere. A run the API rejected has no `checks.txt`, so a resume retries it, and an expired login stops the matrix with the login command instead of leaving an empty reply.
- `run-matrix.sh --stage` runs two reps per arm and extends to `--reps` only where an arm's two replies differ or the arms match. In the one five-rep matrix on record, two reps kept the direction of every saturated arm. They misread every arm at 3/5 in four of ten subsamples, and the flag spends the extra reps only on that kind.
- The `writing-pull-requests` scenario pins its branch to a fixed pair of commits, PR #2 on the main it merged into, instead of whatever is checked out. The diff the model reads is six files on any day and cannot carry the rule under test.

## 1.0.0

The three objections to this number in `0.1.0-beta-1` no longer hold: the plugin has a git remote, `prose-scan.selftest.sh` covers the prose scanner, and it ships five skills.

- Added `audit-vs-fix-discipline`, `writing-docblocks`, `writing-documentation` and `writing-pull-requests`, moved out of `~/.claude/skills/`.
- Hooks moved from a plugin-level `hooks/hooks.json` into each skill's frontmatter, so a hook registers when its skill is invoked rather than for every session.
- Scripts live under `skills/<name>/scripts/` beside the skill that owns them.
- Installable with `npx skills add stuartshields/stuartshields-skills` as well as through `/plugin`. Hooks locate their scripts through `${CLAUDE_SKILL_DIR}` instead of `${CLAUDE_PLUGIN_ROOT}`, which is unset outside a plugin.

## 0.1.0-beta-1

Renumbered down from 1.0.0. The plugin has no git remote, no test file and one skill, which is not what 1.0.0 claims.

Cut for size and for staleness, after an audit found the document rotting even though the rewrite rule was working.

- `SKILL.md` 121 lines to 87, the template 68 to 42, on-invoke cost ~4.2k tokens to ~2.2k.
- The template lost Key Files, Git State and the Verification results list. All three asked for a snapshot of the tree, which is wrong by morning.
- Write and update gained a reconcile step: an old document's claims are resolved against the tree before they are carried forward.
- Findings move to a queue the handoff points at, rather than a copy it carries.
- `remind-handoff.sh` measures the document and nudges past a 120-line ceiling, exempt from the "the skill just ran" suppression.

## 1.0.0, withdrawn

Never published anywhere. One skill, `handoff`, with its `remind-handoff.sh` advisory hook. Superseded by `0.1.0-beta-1` above, which is the same plugin under an honest number, so the descending order here is not a downgrade.
